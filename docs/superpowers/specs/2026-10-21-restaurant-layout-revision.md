# Restaurant layout revision

The user requests a concrete visual and layout revision informed by the reference restaurants, because the existing layout feels awkward. This is an authorised revision of the approved restaurant project.

## Reference observations
- Lilia: centred restaurant identity, simple navigation, photography immediately below the header, short image-and-copy sections.
- Published on Main: image-led introduction and clearly grouped, text-led menus with stronger dish/price hierarchy.
- Current problem: approximately 477 px of the desktop first screen is consumed before the photograph begins; repeated slogan sections lengthen the page; dessert occupies half a row with unnecessary empty space.

## Chosen design
Use a compact centred restaurant wordmark and three navigation links, immediately followed by a large dining-room photograph. Place one short restaurant introduction beside the existing food photograph. Follow it with a paper-like seasonal menu: three equal category columns, readable dish names/prices and restrained optional filters. Finish with one visit-planning section containing the useful party/time details and the existing form. Keep typography restrained, olive/cream colours and real photographic texture.

Preserve both edited images without further generation, all 12 dishes, search/category/vegetarian functionality and existing local request behaviour. Do not invent an address, opening hours, awards or business operations. Keep all other sites unchanged except updating the restaurant preview on the portfolio index.

## Acceptance
At desktop size, the photograph is visible directly below the navigation and occupies most of the first viewport. Menu groups have balanced widths without an empty half-row. At 390 px and 320 px, headings, filters, navigation and form remain usable without horizontal page overflow. Check filters, empty-state reset, mobile navigation and validation; run TypeScript and build. Publication remains pending GitHub authentication.
